# Веб-интерфейс Zoe

React + TypeScript + Vite, Tailwind + shadcn/ui, TanStack Query, i18next. Код — `services/web`. Открывается на
`http://localhost:${WEB_PORT}` (по умолчанию 8080), вход — `ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`.
Как пользоваться — в [README](../README.md#веб-интерфейс-и-стек).

## Демо без бэкенда

Все методы API имитируются MSW по `sample_report.json`, прогресс и чат — потоком:

```bash
docker compose --profile mock up -d --build web-mock
```

Открывается на `http://localhost:8081` (порт — `WEB_MOCK_PORT`), логин `admin` / `admin`. В демо-режиме прогон
документа с `fail` в имени файла завершается ошибкой — чтобы показать экран сбоя.

## Что есть

- Вход; «Документы» — загрузка PDF/DOCX/MD/TXT перетаскиванием, история прогонов.
- Запуск прогона: провайдер, модель, опции (верификатор, атомарные подтребования, чек-лист, уточняющие вопросы,
  «Спросить меня во время прогона» — прогон останавливается на вопросах автору, ответы учитываются в нём же).
- Экран прогона: конвейер агентов с прогрессом по SSE и журнал прогона деревом.
- Отчёт: текст документа с подсветкой цитат ↔ список дефектов, фильтры, решения по дефектам (принят / ложное
  срабатывание / исправлен + комментарий), вкладки «Сводка и итог», «Нарезка», «Матрица», «Проверка набора»,
  «Чек-лист», «Паспорт»; вопросы автору с ответами и кнопкой «Перепроверить с ответами»; выгрузка PDF/DOCX/MD/JSON;
  чат по отчёту.
- «Агенты» — схема конвейера: роль, входы, выходы и связи каждого агента и проверки кодом.
- «Поиск» по прошлым прогонам; «База знаний» — вики (заметки со ссылками `[[…]]`, граф, папки), которую агент
  учитывает при проверке.
- «Расход токенов» — дашборд вызовов LLM, токенов и стоимости по дням и провайдерам; «Журнал аудита».
- «Кабинет»: «Провайдеры» (мастер подключения: провайдер → учётная запись → модель → параметры → проверка; пресет
  для vLLM), «Параметры», «Учётная запись» (язык, тема, пароль).

## Языки

Файл на язык в `services/web/src/locales/` (`ru.json`, `en.json`, `kk.json`). Новый язык — новый файл, он появится
в переключателе сам. Недостающие строки показываются по-русски.

## Тема и стиль

Все цвета, радиусы, тени и шрифты — CSS-переменные в `services/web/src/index.css` (светлая и тёмная тема).
Визуальный язык: тёмный фон с точками `.bg-dots` (тёмная тема по умолчанию), тонкие рамки вместо теней, прямые углы,
моноширинные метки `.label-mono` с цветным квадратиком, оранжевый акцент `--primary` для «агент работает»,
бирюзовый `--teal` для «готово». Экран прогона — изометрический конвейер агентов (`features/runs/AgentScene.tsx`,
стили `.rc-scene`, `.rc-st`, `.rc-layer` в `index.css`); вкладка «Сводка и итог» — статистика отчёта
(`features/report/SummaryTab.tsx`). Шрифты Geist и Geist Mono (OFL) встроены в сборку — работают без интернета.
Перекраска — правка токенов, компоненты не трогаются.

## Типы отчёта

Генерируются из JSON Schema контракта и лежат в git (`src/api/report.gen.ts`); тест падает, если они устарели.
Перегенерировать после изменения контракта (в контейнере, на хосте ничего не ставится), Linux:

```bash
docker run --rm -v "$PWD:/repo" -w /repo/services/web node:22-alpine sh -c "corepack enable && pnpm install --frozen-lockfile && pnpm gen:types && rm -rf node_modules"
```

Windows (PowerShell):

```powershell
docker run --rm -v "${PWD}:/repo" -w /repo/services/web node:22-alpine sh -c "corepack enable && pnpm install --frozen-lockfile && pnpm gen:types && rm -rf node_modules"
```

## Корпоративный прокси с подменой TLS

Если сборка веба падает на `unable to verify the first certificate`, положите корневой сертификат (PEM) в
`services/web/certs/*.crt` — в git он не попадает, в итоговый образ не копируется
(см. [services/web/certs/README.md](../services/web/certs/README.md)).

Пожелания веба к API — [contract-changes/web.md](contract-changes/web.md).
